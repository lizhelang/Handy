# 热词前缀补全与旧 Handy 词汇迁入

本记录对应 1.0.4。用户后续真实验收确认 `lll` 未显示热词；1.0.5 的接线修复见 [热词实际输入链路修复](2026-09-28-hotword-runtime-fix.md)。

## 用户要求

- 英文开头的热词：输入恰好前三个字母，完整热词成为第一候选；继续输入第四或第五个字母，撤下前缀补全。
- 中文开头的热词：输入前两个汉字的全拼或当前双拼编码，完整热词成为第一候选；继续输入撤下前缀补全。
- 允许词库之外的热词，包含邮箱、英文与中文混合词；保留原有候选选择和基本拼音输入。
- 将旧 Handy 保存的自定义词汇合并到 Inputia 热词。

## 本机词汇迁入

2026-09-28 实测旧 `/Applications/Handy.app` 与原应用数据目录已不在原位置。2026-09-24 的迁移归档仍保存旧程序与数据，未删除或改动这些备份。

从该归档的原 Handy `settings_store.json` 读取 64 条自定义词汇；同一归档的移走目录也是 64 条，较早配置的 57 条均包含在最新 64 条中。Inputia 原有 1 条热词；保留顺序、精确去重后新增 64 条，总计 65 条。

合并前正常退出控制中心，保存权限为 0600 的原配置备份，原子替换配置，仅修改 `settings.custom_words`。重启后设置页已显示旧词汇与原有邮箱。没有修改其他设置，没有把私人词汇写入仓库。

词汇迁入使用本机配置备份，不能由此推断历史、录音或图片是否全部迁移。

## 实现与回归

- 配对共享词协议新增独立 `explicit_terms`，只读取用户 `custom_words`，不把学习词当作前缀热词。邮箱与混合词允许通过；总量限制为 256 词、16 KiB，单词最多 128 字符。
- 中文模式叠加补全候选，不伪造 Rime ID；选取基础候选仍映射回原生或个性化候选索引，保留消费长度。空格、Tab、数字与点击使用同一选择路径。
- 中文前两字读音使用系统拼音转换；全拼兼容与自然码编码均支持，含 `ü` 音节。多音字采用系统读音，本轮未提供用户自定义拼音读音字段。
- 英文模式复用词尾补全，显式词在恰好三字母时优先，第四字母不再由共享显式词补全。三个字母的完整英文热词在英文模式已经直接输入，无需额外补全。
- 共享快照每半秒更新；过期撤下并重绘基础候选。异步选择再次校验输入框、组合、光标位置、权限 epoch、目标、当前共享快照和安全输入状态。
- Rust 协议回归 16 项通过；Swift 全源类型检查及共享词自检通过。合成前缀回归包含邮箱、第四/第五键撤回、退格恢复、英文混合词、三字母词、额度全拼/双拼、南信大第三音节撤回、绿洲 `ü`。
- 热词页面回归、24 种语言键一致性、全量 ESLint、修改文件 Prettier 与 Rustfmt 检查通过。
- 全库 `format:check` 被 5 个未修改的既有文件阻挡：本地模型构建产物 HTML 及 vendor/handy-keys 的 4 个文件。本轮没有格式化这些无关文件。
