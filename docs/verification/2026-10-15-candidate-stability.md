# Inputia 候选闪断与卡顿：1.1.9/build97

日期：2026-10-15（Australia/Sydney）。1.1.9/build97 已完成构建和安装，用户已在本次实际试用中确认稳定性明显改善。用户已明确反馈 1.1.8 没有稳定解决问题，本轮不再研究模型或扩展功能。

## 现场证据

核对运行制品为 1.1.8/build96，两组件权限 ready，后台和 IME 连续运行约 9.5 小时；当时采样 CPU 分别约 1.9%/2.7%，没有编译进程。这是一个时刻的负载，不能据此排除所有性能问题。

只读取产品固定白名单诊断，不收集输入正文、拼音、窗口标题或目标身份。读取窗口获得 pipeline 333 条和 shortcut 81 条；25 次 schedule disabled 与 listener_unavailable 相隔不到 10ms，中位仅 0.977ms。08:42:41–54 的约 1.3–1.4 秒重复失效期间没有新 target_request，符合旧目标被重复注册的路径。保存的证据只有时间与固定元数据，见 [关联统计](candidate-stability-20261015/correlation.json)。

79 次显式捕获请求的排队 p95 为 16ms，执行 p95 为 250ms、最大 1677ms；释放请求曾等待 2001ms。热键注册、共享词验证还有直接服务端目标检查，不能把这 79 次称为全部 AX/IPC。

## 根因和改动

- 快捷注册目标被原生编辑事件判失效后，本地 snapshot 仍可能通过选区检查。原实现把业务拒绝当成握手故障，关连接但保留坏目标；1 秒后重连同一目标，握手再次清候选和在途准入。新实现仅对严格认证、请求 ID 匹配且载荷形状有效的 unauthorized 注册回执撤下对应目标，再重新捕获，保留合法 socket。未知/坏协议及传输故障仍关闭。
- 普通打字导致目标暂时缺失时，原实现也直接关连接。现在退役已明确注册的 lease，等待目标恢复；待注册身份不冒充已注册身份。已有录音保留原停止通道，不自动重放触发。main 仅按 ID 清预捕获归属，仍被其它 typed/retained owner 使用的目标不被误释放。
- 基础候选恢复原本必经 orderOut，再查询宿主，最后 orderFront。现在立即清旧正文、编号和选择外观，在原可见窗口内恢复通过原校验的基础候选；失焦、安全输入等失败仍关闭。独立显示 token 防止同步重入及迟到恢复覆盖新窗口内容，不改变候选准入或租约。
- 相同候选不重复重建行视图，相同位置和尺寸不重复设 frame，已可见窗口不重复置前；新内容先完成布局再显示。
- 中文按键不再无条件执行仅英文需要的选区与 marked 查询；已有英文追加、删除及快捷键语义保持。

## 验证

用真实监听 timer、注册协议方法、握手屏障及完整 Personalization 执行回归，传输和原生目标边界为替身。修前同坏目标在 2.65 秒内 opens/barriers/disabled 各 3 次，修后各 1 次（首次连接），随后撤下旧目标。五类场景覆盖目标缺口、确定拒绝、新旧租约交接、录音停止及坏协议；迟到旧 ID 和其它目标 owner 也检查。旧源码在同一业务断言失败，修后通过。

基础恢复 36 项、空白交接 12 项、真实 NSView/窗口显示方法刷新 5 组、中文按键路径 6 项通过，独立复审通过。配套 Swift 类型检查与权限边界检查通过。完整成套构建已执行项目要求的原生自检并通过。

这些证据不能替代实体键盘在所有应用中的稳定性验收。一次新建 TextEdit 文稿的自动化尝试仅收到 Latin 字符，工具不支持单独 Shift，未取得有效中文输入证据；该合成测试文稿已存到 /tmp/inputia-smoke-baseline-20261015.rtf 并关闭，未操作现有文档、微信或账号。

保留原候选准入的安全合同；原生候选在增强排序状态下的异步准入、特殊控制键最长 750ms 的等待仍是已知延迟路径，本轮没有凭候选来源标签跳过核验。冷 policy 首次握手回包自作废的问题也没有借此次修改放宽隐私代数校验。不能据本轮修复宣称所有延迟为零或所有应用已通过。
