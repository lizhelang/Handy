# Inputia 连续联想、排队与前文修复

日期：2026-10-14。1.1.8/build96 已安装，实体键盘交互待用户确认。源码修复及安装成功不能替代实际键入验收。

## 用户反馈与范围

用户确认上一版可以用空格/数字选择，但只能选一轮；推荐慢、上下文质量弱。用户同时明确实时输入完全本地，联网只供预先取得或后台更新本地资源。

- 推荐经原准入、最终字段证明并成功插入后，继续下一轮；本轮重新五秒，等待保留空白原窗。旧计时器、先前排队的键和系统连发不能自动选择新列表。
- 捕获输入目标的队列最多等待 16 项；失效的排队请求在连接和原生查询前取消，逐项让出队列。已经开始的请求不重放、不跳过回执和释放。
- 前文最多 512 个 Unicode 标量，只合并本输入法实际完成的插入。已有字段身份、服务实例和连续光标位置必须同时匹配；缺证明不追认之前片段。查询和准入采用同一完整值，学习反馈仍为末 64 个标量。
- 普通拼音开始时，仅在原有效期内暂留当前字段证明，下一捕获完成后释放；不用于插入，不延长租约。边界变化和原到期也释放。
- 真实隐私撤销、服务或版本变化清前文；同完整版本的再次握手仍清共享候选与目标许可，但保留本次自有输入。首次握手仅清不能证实的旧前缀。先完成主线程清理，再发 ACK。
- 同步输入法查询可能重入；过时调用只能返回，不能擦掉内层刚建立的新前文。无上下文时不增加选区/marked 查询。

## 证据与限制

生产候选查询/准入的 Rust 集成测试 23 项通过，其中长查询与短反馈合同覆盖 512 字中文、四字节 Unicode、513 标量拒绝、控制字符及 65 字反馈拒绝。公开词库 356,723 条，100 次独立查询 debug p95 为 5.715ms；此值不包括原生输入框与跨进程交接。

原生回归执行生产方法，输入法客户端、传输及部分系统边界仍为替身。覆盖三轮真实调用链、按键回放、动态租约下的字段交接、重入、隐私通知及期限；不能声称它等价于用户在所有应用中的实体键盘结果。构建会再次执行对应自检并编译配套组件。

固定错误码诊断只记录操作编号、排队/执行耗时及原因，不记录正文或目标身份。未操作聊天窗口、账号或系统权限数据库。

## 本地语义模型探索

苹果设备端模型和官方 Qwen3-1.7B 本地模型均完成公开合成文本测试。Qwen 单独推理足够快，但最终匿名评分 raw 10/20、few-shot 6/20 有用，长段落均 2/4；仍有重复和无法自然拼接的输出。没有把这些模型默认启用，也没有把单独 runtime 的速度当作产品速度。

本版修复连续交互、软件排队及可证明的前文保留，仍采用已有本地词库和学习算法；不宣布神经语义联想完成。完整路线、来源、原始反例及复跑材料见[离线联想边界](../architecture/offline-predictions.md)。
