# 1.1.33：用户确认回填后从语音与键入历史学习"上一个词→下一个词"

日期：2026-10-23。分支 `codex/prediction-ngram`，代码提交 `2d0238d7`，版本提交 `b36dd122`。承接 [1.1.32 记录](2026-10-23-prediction-keys-1132.md)。

## 目标与边界

用户要求：从语音与键入历史中抽取个人搭配用于上屏后联想；对所有人保持现有设计，只有用户在控制中心选择来源并确认后才学习，不自动读取历史；先在本机历史开发段验证；不得删除任何历史。

- 回填入口不变：控制中心"知识库 → 输入习惯与联想"，选择学习来源后点"从所选历史学习"并确认，每批默认 200 条（最多 500），"继续学习下一批"直到完成。没有新增自动回填，本轮也没有替用户执行回填。
- 回填时用联想表词表（约 8 万词）正向最长匹配切词，标点、英文与词表外的字处断开，相邻词对按来源与修订写入 `history_bigrams`，触发器维护 `history_bigram_totals` 汇总。每出现一次计 0.1 个人证据。
- 历史词对只服务上屏后联想，不参与拼音候选重排。上屏后联想不再读取原有的"导入整句"：开发段上它使首选命中下降（语音 7.16% → 5.87%），且每次查询要逐条核验来源，p95 升至约 23 ms。拼音候选重排对整句的使用不变。

## 删除与修改后的撤销

撤销只删除学习库中的派生数据（`imports`、`evidence`、`history_bigrams` 及汇总），不删除、不修改任何语音、录音、键入或剪贴记录。

- 展示前核对：含历史贡献的推荐（最多 3 项）在展示前按次数从高到低、每批 8 条核对其来源，至少一条现存来源才展示。判定与后台来源核对一致：来源类型开放、应用未被排除、记录存在且修订一致；语音与剪贴板另核对统一投影背后的源库身份与源记录修订。途中发现的失效来源立即撤销其全部学习并推进学习世代，本轮作废、下一轮重查。
- 未被抽到核对的失效来源仍由后台核对（每 30 秒一轮）扣除，只影响排序，不会让已删内容单独出现。
- 遗忘某个词、清空个人学习、重新回填同一来源、后台核对发现失效，都同步删除对应词对，汇总随触发器扣减。

## 性能

展示前核对最初使 p95 达到约 8 ms。逐项采样发现主要开销是每次查询新建 SQLite 连接、加载表结构和解析语句，处理如下：

- 每个候选找到一条现存来源即停止核对，不再全量核对数百条来源；
- 历史词对加 `(previous, normalized, count DESC, origin)` 索引，分页取来源不再临时排序；学习证据加 `(origin, normalized)` 索引；
- 联想查询结束后把已初始化的学习库连接放回池中复用；来源库与来源开关的只读连接也在查询间复用。按文件身份判断，库文件被替换时重新打开；池有上限，归还时清理已不存在的文件。

连接复用同时让不回填时的 p95 从约 2.4 ms 降到约 2 ms。
