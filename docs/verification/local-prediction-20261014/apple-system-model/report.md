# Inputia 端侧短续词：三配置留出实验

日期：2026-10-14。只写本临时目录，没有产品源码改动。机器为主任务确认的 M2 Max / 32GB / macOS 27.2；实际编译使用 Swift 6.4、macOS 27.2 SDK。所有输入为本轮自造公开文本，与前轮10个上下文无重合。未读取私人数据，没有远程模型调用、下载或资源激活。

## 预先固定范围

采用3条fewshot示例，只比较3个配置；12个新上下文均在运行前固定，看到留出输出后没有继续修改提示或重跑调参。它们是提示示例外的自造留出样本，仍不是自然用户语料或大规模泛化评测。

```text
你是中文输入法的光标续写模块，不是聊天助手、摘要器或咨询助手。
先默读完整前文，再给出能够直接拼接在前文最后一个字后面的短续词。把“前文+续词”连读，语法必须自然。续词不重复前文，不解释，不给标签或编号。每项一至六个汉字，最多三项，不要为了凑满而输出近义重复或不自然短语。
只能提出符合已有语境的可能接续，不要增添原文没有提供的日期、数字、质量结论、承诺或其他具体事实。不确定、句子已经结束且没有自然接续时，可以不给候选。
示例一：前文“水已经烧开了，我准备把面条”，可续“放进去”“下锅”。
示例二：前文“这份报告还没检查完，发出去之前应该”，可续“再核对”“先检查”。
示例三：前文“型号和数量都已确认。”，没有自然的短接续，返回空。
```

- A / three：结构化数组，允许0—3个候选，各1—6字；实际生成上限72 tokens。
- B / single：同样的示例指令，补充本次只给一个续词，可返回空字符串；实际上限32 tokens。
- C / prefix：与A完全相同，但prewarm传入整条本次提示前缀。
- 所有配置均先prewarm，再留出1秒准备窗口，保证A/C差别是是否提供具体promptPrefix；同时报告这1秒在内的总耗时。case间轮转A/B/C顺序，降低固定先后顺序偏差；每个请求使用独立session，避免前一个样例对话污染。
- 正常请求总截止5秒，异步Task取消；外部进程watchdog210秒。单独生成中途取消实验100ms、无人为预热等待。
- 首完整候选计时：数组出现第二项时可确认第一项已完整，否则取流结束；单候选取完整流结束。这是保守可用时刻，不是首token。生成阶段不包含已明确列出的1秒预热窗口；总时间包含session构造和该窗口。

## 实际时延

| 配置 | 首完整候选 p50 / p95 / max ms | 最终生成 p50 / p95 ms | 含准备总时间 p50 / p95 ms | 形状有效 / 空结果 / 超时错误 |
|---|---|---|---|---|
| A 三候选 | 691.92 / 828.34 / 828.34 | 705.57 / 891.51 | 1771.21 / 1964.79 | 12/12 / 0/12 / 0/12 |
| B 单候选 | 520.81 / 619.97 / 619.97 | 520.81 / 619.97 | 1577.71 / 1685.28 | 12/12 / 0/12 / 0/12 |
| C 前缀预热三候选 | 697.93 / 741.94 / 741.94 | 706.27 / 807.66 | 1769.08 / 1871.49 | 12/12 / 0/12 / 0/12 |

每配置n=12，因此nearest-rank p95等于样本最大值；不能解释为稳定的生产尾延迟保证。

C与A的候选逐字一致 12/12。C首候选相对A的配对差值中位为 3.24ms，范围 -86.40 至 71.22ms；该小样本没有显示出稳定且明显的上下文预热增益。

100ms取消实验实际 106.22ms 返回 `CancellationError()`，候选为空。三配置正常请求均未超时。没有受控清空系统模型常驻状态，故不新增冷启动结论。

## 判断

当前三配置均不建议接入默认候选显示。异步预取可以把模型等待移出按键路径，但无法修复这次出现的语言质量问题；单候选更快，也仍有明显不合格结果。

- “非常谢谢”→“不客气/没关系”，把续写变成回答；单候选“了事”更不适合。
- “我想”→“想喝茶/想休息/想出门”，违反不重复前文的要求。
- “首先要检查”→“查看设置/检查传感器/清理通道”，只是主题相关，直接拼接出现重复谓语。
- “准备先补上”→“添加项/检查后”，不能稳定满足末尾语法。
- 句子结束且允许空结果，仍返回“准备前往/确认细节/讨论方案”，没有表现出可靠弃权。
- 正向样例也存在：小说→“往下读”；142字段落→“修复封面”；鱼缸与打印机的相同尾句得到不同主题词。这支持它能利用上下文，不支持它已达到中文输入法续词质量。

这些是明确可读的反例与观察，没有把主观判断伪装成准确率。建议保持快速本地确定性候选为默认来源，当前系统模型仅留在隔离评测；若将来达到锁定留出质量门槛，再考虑带字段/上下文代数、截止、取消、选择期间冻结的本地异步预取。

## 官方端侧依据与预热边界

Apple官方将 [SystemLanguageModel](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel) 定义为设备端文本基础模型；本脚本显式使用 `SystemLanguageModel.default`，未实例化PrivateCloudComputeLanguageModel，也没有API客户端或工具调用。此结论针对模型执行路线，不声称抓包证明系统所有后台进程零联网。

Apple的 [prewarm(promptPrefix:)](https://developer.apple.com/documentation/foundationmodels/languagemodelsession/prewarm%28promptprefix%3A%29) 说明可提前处理提示前缀，建议在正式响应前留出至少1秒，且不保证资源立即加载。本实验据此显式计入准备窗口。SDK接口已在本机27.2的FoundationModels.swiftinterface核对。

## 复跑

```sh
xcrun swiftc -parse-as-library -O Bench.swift -framework FoundationModels -o bench
./bench all
./bench cancel
```

正常请求有5秒内部取消；复跑同样应加外部进程总截止。统计见summary.json，所有原始结果见results.jsonl，取消结果见cancel.jsonl。
