# 1.0.7 剪贴历史默认快捷键与菜单提示

## 授权需求

默认 Ctrl + Shift + V 打开剪贴历史，允许用户修改，输入法菜单括号显示当前快捷键。

## 实现

统一产品使用主程序注册的全局快捷键，不再同时触发原生输入法硬编码的本地召回候选。剪贴历史菜单仍调用同一个主程序浮窗入口。菜单状态通过已有认证菜单协议返回当前快捷键和启用状态，标题在状态刷新后更新，旧服务缺失字段时兼容显示默认快捷键。

快捷入口与剪贴板采集开关解耦：关闭采集仍可打开已有历史；本轮不改动采集开关。既有用户的旧默认 Cmd + Shift + V 迁移到新默认并启用，用户自定义键及其启用选择保留。

通用和剪贴历史两个页面都复用已有快捷键录制组件，读写同一 clipboard_history 绑定，支持修改和恢复默认；两处设置和菜单共用当前配置。

## 安装与界面核对

主程序和输入法已签名成对安装为 `1.0.7 / 81`，更新器返回 `candidateUpdate=true tccChanged=false previousRecordingsReplayed=false`，输入源和运行身份检查通过。实际 store 已迁移 schema5：当前/默认绑定均为 `ctrl+shift+v`，快捷入口已启用；采集仍为原来的 true。启动日志确认 `Registered handy-keys shortcut: clipboard_history ... key: Some(V)`。实际热词自检仍为 65 条，lll 匹配 1 条。

已在安装后真实界面核对通用和剪贴历史两处的“剪贴历史快捷键 / Ctrl + Shift + V”，点击录入显示“请按键…”，点击外部取消后恢复默认且输入控制已就绪。窗口最终留在通用页。

本机 CUA 合成按键没有交付到 handy-keys 全局监听/录入器：按组合键没有打开浮窗、录入器也没收到字符，因此未将自动化按键当作实体键盘触发或自定义保存成功的证据。默认、注册、入口与取消已核对，实际组合键触发仍需实体键盘验收。系统输入源菜单的 AX 访问超时，括号文本验证来自真实配置、协议和原生格式/构建检查，不声称视觉核对该系统菜单。
