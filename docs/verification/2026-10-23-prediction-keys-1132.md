# 1.1.32：联想不再重复刚上屏的词，改为空格选高亮且只显示 3 项

日期：2026-10-23。分支 `codex/prediction-ngram`，代码提交 `2e662711`，版本提交 `41a96b24`。承接 [1.1.31 记录](2026-10-23-prediction-ngram-phase1.md)。

## 用户反馈

1.1.31 实测"确实改善一点"。打"在这"后联想出"个"，选中后下一轮仍显示"1 个 2 也使 3 问题 4 的 5 意义"，"个"后面再推"个"组不成句子。用户同时要求：联想不显示编号、不能用数字键选（自己要打数字时会误选），只用空格选，左右方向键或 Tab 切换，只显示两三项即可。

## 原因

在本机学习库的只读副本上重放（副本用新随机密钥，未复制真实密钥，用后删除）：输入法传给服务的前文确实是"在这个"，结果与截图完全一致，来源为 个（个人）、也使（个人）、问题（公共）、的（个人）、意义（公共）。只用公共表时为"问题 / 意义 / 过程 / 时期 / 概念"。

"个"来自刚选中时记下的学习记录（前文"在这"→"个"）：下一轮前文"在这个"与其前文共享片段"在这"，被当作弱语境证据，把刚上屏的这一步推了回来。1.1.31 的个人层对"只有片段重合"的记录也计入（锚点强度 × 0.5），这类记录并不说明接下来写什么。

## 改动

- 个人层的下一个词只认两种证据：完整前文相同（原权重）与前文最后一个词相同（× 0.5）。按前文末字建表达式索引 `evidence_previous_last` 取回后在内存中核对整词；只新增索引，不改表结构。
- "前文 + 该词"正好是当前前文结尾的记录（刚上屏的这一步）不再推荐。
- 联想最多 3 项、不显示编号；无修饰空格选当前高亮项；左右方向键与 Tab（Shift+Tab 反向）循环移动高亮，先于前文与字段边界处理，不移动光标、不结束本轮；数字键不选择推荐，直接结束本轮并照常输入；只有一项时方向键与 Tab 照常交给宿主。普通拼音候选的数字选择不变。AGENTS 中原"空格/1 选第一项、2–9 按序选择、Tab 保持兼容"的规则已按用户要求改写。
- 评测导出脚本支持较早时间窗作开发段，并清除副本中已安装版登记的联想表（否则旧引擎对照会被它带成新引擎；本轮第一次对照因此作废重跑）。

## 实机试用（待用户确认）

1. 打"在这"空格上屏：联想最多 3 个、没有数字；选"个"后下一轮不再出现"个"。
2. 联想显示时按 → 或 Tab 高亮移到下一个，← 或 Shift+Tab 移回，光标不动；按空格上屏高亮的那个。
