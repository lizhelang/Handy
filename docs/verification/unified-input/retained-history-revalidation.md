# 旧策略历史重核验

范围：P1 同步恢复分项，2026-09-05；完整目标继续进行。

## 问题与修复

忘记术语前移全局 policy epoch 后，源 outbox 仍可能含较旧 epoch 的合法历史。原来的严格 apply 拒绝它们，会让消费游标永久停在原位置。

- 保留严格 `apply_change/apply_changes/restore_source_snapshot` 的原版本检查。
- 新增只用于已持久化历史的 `HistoryRetentionPolicy` 和 `apply_retained_history/restore_retained_history`，授权必须与规范库当前保留规则一致；未来 epoch、伪造规则仍拒绝。
- 原始事件内容与摘要不改写；重新核验不向 learning ledger 添加任何贡献，也不开放远程上下文。
- SyncPump 对队列与回收后的完整快照都走重核验；规范库提交后确认，再推进源 epoch，使新捕获事件沿新版本继续。
- 已知敏感来源由默认排除规则处理；unknown 历史按批准方案保留原本地历史可用性，但不获得学习权。
- 正式自定义排除设置写入及新采集隐私元数据仍须在设置/采集接线阶段完成；本轮不能证明全部敏感场景已覆盖。

## 独立审查

审查发现：已存在同 revision 条目会被版本护栏视为 stale，重复事件也会在摘要回执命中后直接返回，导致现行规则拒绝的旧条目没有撤销。

已增加 `withdraw_disallowed_record`，在重复回执及源版本判断前，独立核验规范库当前条目并在同一事务中撤销正文、修订、学习贡献，写无正文策略排除记录。检查当前规范版本而非旧事件正文，防止旧事件误删更新后的合法来源。原事件摘要不修改。

独立复核确认该 P2 已关闭，新增测试的重复事件与同版本快照两条路径通过；之后更高版本重放也无法复活条目。

## 验证

- `sync_pump` 4 项通过：跨版本排队历史重核验、ACK 后重建、更高当前策略恢复、后续源序列继续；忘记后重核验不重新授权术语。
- 新增授权测试：严格 API 仍拒绝旧 epoch；伪造保留规则拒绝；原事件重复摘要一致；修改正文重用事件 ID 冲突；未来 epoch 拒绝；敏感来源不进入本地投影。
- 同 revision 快照/同事件重放策略撤销测试通过，独立审查者另行复跑通过。
- Runtime Clippy `--all-targets -- -D warnings` 通过。
