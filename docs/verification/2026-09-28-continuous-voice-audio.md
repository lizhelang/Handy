# 1.0.8 保留连续完整语音输入音频

## 用户故障与证据

用户报告语音经常被裁断，整句内部音频混乱。实际设置启用 Silero VAD；当前选用 Whisper 整段识别，近期记录的转写也没有后处理字段。本轮诊断只读取时长/样本计数/设置和字段长度，不打印私人语音或转写正文。

录音层的 handle_frame 原先将 VadFrame::Noise 完全丢弃，最终 samples 和历史 WAV 都是筛选后重新拼接的音频，可能删除停顿、轻声或未达到 onset 的短尾词。日志中墙上录音时长大于样本时长仅是佐证，不能单独推断差值都是误删语音。

SmoothedVad 的 speech 恢复分支重新发送全部 prefill，包含此前已发送帧。确定性帧脚本 `[T,T,F,F,F,T,T]`、prefill3/hangover2/onset2 会输出 `[1,2,3,4,4,5,6,7]`，第4帧重复；现有录音 emit 同时保存/传递这份缓冲，会影响样本顺序与内容。

停止时仅记录 withheld tail，不补回未确认 onset 尾帧。EOS 排空和重采样 finish 已有尾块/绝对超时保护，未发现需要更换它们的证据。

ASR actions 的 stop samples 原样复制保存 WAV，再交给 batch run，未另行分块。当前依赖的 Whisper/Qwen3-ASR 均无有效流式最终路径，不能将本次裁断归因于预览顺序。

## 修复原则

识别输入、历史 WAV 和音频回调均使用连续的每个重采样帧，按原顺序恰好传递一次。开启 VAD 仍检测活动并提供诊断，但检测不能删除或拼接音频，也不能把未确认 onset 的轻声短句硬判为空录音。保留开始/停止、取消隔离、EOS 排空和尾块处理。

SmoothedVad 自身的 prefill 输出只包含未发送帧，避免其他调用者重放旧帧；完整音频链路不再依赖其聚合输出。界面说明同步为非破坏性的语音活动检测。旧录音和用户模型/检测设置保留，不重新改写历史。

## 验证与识别边界

音频工具层 86 项回归全部通过。新增回归经过真实 run_consumer 线程、Stop/EOS 握手及不规则输入块，逐样本验证 Offline、Streaming、Disabled 三种策略的最终 PCM 与回调一致且恰好一次；覆盖内部 Noise、短停顿、未确认 onset 尾音、停止时部分帧补零，以及 Disabled 检测调用次数为零。既有开始/停止隔离、重采样重置、EOS 排空及绝对超时测试也通过。独立审阅未发现阻断问题。

原生输入法 1.0.8 / build82 构建和现有自检通过；翻译键一致性及修改文件格式检查通过。主程序 tsc/Vite 与 Tauri release 构建通过，两个已安装组件均为 1.0.8 / build82。最终更新器返回 candidateUpdate=true、tccChanged=false、previousRecordingsReplayed=false，运行身份校验通过。真实 UI 显示 v1.0.8 和“Inputia 输入控制: 已就绪”；TIS 确认 Inputia 输入源选中。原 Whisper 模型、Silero/VAD 设置保持，热词自检 loaded_count=65、prefix_matches=1。

完整 PCM 送入识别器不等于保证任意长度语音逐字正确。当前 Whisper 后端每个窗口最多生成 256 token，耗尽后缺少明确的截断标记；Qwen 超限会返回错误。本轮没有证据说明这些限制命中用户录音，因此没有扩大修改后端生成策略。

真实麦克风验收仍需用户说一段带句中停顿、轻声和短句尾的完整话，分别检查开始/停止录音、保存音频连续性和最终转写；合成帧回归不能替代实体说话质量验收。

## 安装时发现的本地缓存问题

前两次安装因组件无法启动而自动回滚。直接启动原 1.0.7 也退出78并报告“候选数据包含符号链接或特殊文件”，证明并非本轮音频代码导致。定位到当前 Whisper Hugging Face snapshot 的模型符号链接；它指向同一 profile 下的 blob，大小 1161143008 字节。

保留原 blob 与链接备份，将 snapshot 入口换为同内容、权限600的普通文件后，既有目录安全检查通过。没有放宽安全检查、改变授权、切换模型或删除用户数据。最终安装成功；这是本地缓存修复，尚未改变下载器未来创建链接的策略。
