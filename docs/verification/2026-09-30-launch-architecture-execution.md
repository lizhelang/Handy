### 第三批：跨库删除恢复

现有 `HistoryService::delete_item` 进入耐久 `requested → source_applied → projection_revoked`，请求只保存身份/修订/摘要，不保存正文或附件路径。源事务同时保存成功或 CAS 拒绝回执，重入优先返回原回执，不因后来修订恰好匹配而重新删除。

启动按页审核包括终态在内的真实源回执、源实例、墓碑、旧修订与统一学习贡献撤销证据；恢复及审核未结束时阻止正文读取与新派发，保留 finish/cancel/状态请求。后台轮转故障项，避免一条失败记录饿死后面的恢复任务。

独立复审发现并修复两个问题：仅信任 `projection_revoked` 字符串，以及仅信任 `rejected/source_revision` 标签。现在必须核实真实源事务证据。新增故障恢复 21 项、其他相关模块 43 项，共 64 项通过；局部格式与 diff 检查通过。两轮修复后的只读复核为 CLEAR。

此阶段明确记录 `attachment_cleanup=not_started`，不宣称附件或全部学习域已忘记。附件 GC、跨域遗忘、Tauri/UI 删除进度和真实旧版本回滚仍待完成；测试只使用临时数据库。

### 第四批：原生发布目录信任核心

新增 `inputia-release`：P-256 签名域、严格 canonical JSON、连续双阈值根轮换、不可改写历史归档策略、新 feed v2、manifest/attestation/报告原始字节摘要绑定、逐库兼容与源版本绑定回滚。产品唯一元数据补齐 updater/bootstrap 的固定身份。现有 Python 结构工具保留其“不代表密码验证”的报告；原生库尚待签署流水线和实际 UpdateService 接入。

耐久 `TrustStore` 固定用户目录，逐目录句柄校验、独占文件锁、完整根链重验、各频道独立序号、观察时间单调、初始化完成标记、原子文件/目录同步。已观察到过期后即使回拨系统时钟也拒绝旧 feed。只有提交了防重放状态的频道可以从公开接口产生 `AuthorizedReleaseMetadata`，该类型仍不替代 Apple 验签、原生库状态或验收 gate。

独立复审发现并关闭：原始签名封套的空白/签名排列可冻结后续轮换；当前角色阈值变化破坏历史归档；签名数量不足以覆盖两套大阈值根；依赖特性改变 canonical 字段顺序；helper 身份未固定；状态文件丢失会静默重置；纯元数据入口绕过持久高水位。对应改为签名语义摘要、固定历史策略、双根签名容量、显式递归排序、单源组件 ID、耐久初始化标记和单一公开授权入口。最终针对后两项的复核为 CLEAR。

验证：原生 16 项通过（显式开启 `serde_json/preserve_order`），Clippy all-targets `-D warnings` 通过；Python 发布/验收共 46 项通过，配置无漂移。涉及临时签名键、合成清单/报告和隔离目录，不涉及真实签名凭据、已装软件或用户数据库。CI 增加该原生 crate 的合同回归。

P4 仍待原生下载/解包/安装器接线、验收后签署流程、离线根恢复/新装授权、正式公证与渠道操作；不宣称整个发布体系或 G8–G10b 完成。

### 第五批：原生配套更新事务核心

新增 `inputia-updater`，实现真实文件系统事务而非仅状态枚举。`prepare` 只读；`begin` 独占事务 ID/进程锁，固定安装收据路径，按组件同卷 stage/backup/failed 执行不覆盖移动。每一步先持久 intent，再 rename/目录同步，再持久结果。原配对清单和旧收据保留，新收据最后切换。维护标记独立于程序目录，先于替换发布，在 postcheck 和开放写入日志耐久之后移除。

恢复对照磁盘身份与摘要，不信任阶段字符串；未知文件、源变化或坏备份进入修复错误。回滚只恢复二进制和收据，不用旧数据库覆盖现有用户数据。已开放写入后，必须重新停双端，再取得绑定当前维护 epoch 的逐域兼容证明，才允许移动旧程序回来；每次恢复均重验动态证明。

独立复审关闭：单字段日志篡改跳过写入后回滚门槛；请求回滚未完成却允许第二事务进入；正常 `/Applications` 权限被误当数据损坏。当前执行范围明确为 `User`，`LegacySingleUser` 返回 `PermissionRequired`，等待具有独立信任策略的授权迁移助手。最后对停写时序/epoch 的窄复核为 CLEAR。

实施代理验证：完整 20 项故障矩阵通过（183.45 秒）；最后接口收紧后，相关 rollback 5 项和 marker 1 项通过，包含新增第 21 项。覆盖更新 28 / 回滚 18 个 rename 前后、全部 journal 与 marker 断点、恢复幂等、真实子进程锁、未知文件/备份保护、矛盾日志与待恢复互斥。Clippy all-targets `-D warnings`、fmt 与 README 格式通过。主代理按独立复核与定向回归记录，不重复执行未改变的矩阵。

没有默认通过的生产 `NativeAdapter`。真实 Security/TIS/SQLite 适配、外置签名 bootstrap/恢复注册、受限 postcheck、下载归档和 GUI 仍继续实施；20/21 项合成文件系统证据不能代替 G8/G9 的真实安装验收。本包未操作日用安装或真实数据库。

### 第六批：维护启动门禁与归档字节验证

共享 `inputia-settings::maintenance` 从系统用户目录和实际 UID 定位固定维护标记，拒绝坏内容、错误权限和链接。主程序、输入法 Host、设置 shim、无 session C ABI 与 session 构造入口在打开业务数据前检查；旧 v1 入口同样受约束。只读 postcheck 只返回绑定事务/epoch/收据的元数据，明确不宣称验签或运行握手成功，也不提供普通启动绕过参数。

实施代理验证：设置 15 项、C ABI 1 项、Swift 合成启动场景 7 项通过；普通/v2 后台编译及完整 Host/shim typecheck 通过。更新核心复用共享标记后的两项相关回归通过。独立窄复核 CLEAR。它解决新进程启动门禁；已经运行的进程停写、启动检查后的竞态，仍需要原生维护屏障完成，不以一次标记读取代替。

原生发布库增加清单所列组件归档、分发包与配对清单的真实字节校验：逐目录句柄打开、有界流式摘要、准确大小与总预算，拒绝软/硬链接、重复 inode 与读期间变化。原生发布测试增至 18 项，显式开启 `serde_json/preserve_order`，Clippy 严格检查通过；Python 发布/验收增至 47 项。该证明止于本次读取，后续暂存、解包与 Apple 代码身份仍须独立验证。

本节仍只记录临时夹具、编译与合同回归；没有替换已装程序、退出日用进程或改变真实业务数据。

### 第七批：附件生命周期与播放租约

新增耐久附件目录：导入预留、同目录临时写入、WAV/PNG 格式和摘要验证、原子发布与源修订引用；源正文不依赖附件成功。相同内容并发导入在提交时合并真实代际并回绑 pin，删除后同内容重导入可生成新代际。源删除回执保存原始附件清单，恢复逐项核实当前与历史修订引用，未知旧回执不会伪报清理完成。

历史/剪贴板全部删除、清空和保留期清理统一进入生命周期，不再旁路 unlink。GC 必须取得源写者排他屏障，维护期间暂停，按游标轮转失败项；Active 播放租约按进程恢复，Export/Update pin 保持事务语义。异步获取采用 operation ID：取消先记录墓碑，迟到获取不能重新持有租约。前端暂停、结束、失败和卸载均先停止媒体读取再释放，恢复播放重新申请。

实施代理验证：runtime 全套通过（47 个库单测与全部 integration suites）；随后新增 PNG 纵向用例后，附件专项 24/24 通过。正文/WAV 失败回归 1 项、历史模块 6 项通过。主代理的播放 UI 专项 3/3 通过，包含卸载后原 DOM 元素已暂停、无 src，严格 pause→load→release 顺序。独立审查先发现并修复代际、崩溃容量预留、历史清单、伪造终态、清理饿死、并发导入与 React 卸载 ref 时序问题，最终对应窄复核 CLEAR。

边界：测试使用临时库、WAV/PNG 夹具与模拟媒体；不能代替日用音频或原生 GC 验收。旧资源首轮同步审计及单文件 GC 仍有队列延迟风险，性能门槛尚未通过；非 Unix 文件物理操作保守暂停。本包不宣称完成全磁盘预算、全模型备份或 P1 全部隐私合同。
