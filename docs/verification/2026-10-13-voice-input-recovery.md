# Inputia 语音快捷键恢复与第三方输入法粘贴修复

日期：2026-10-13。范围是本机 Inputia 修复，不代表公共发布或所有应用兼容性验收。

## 现场证据

- 已安装版本为 1.1.2 build 90，来源提交 `f6b397fd`；进程自 10 月 3 日持续运行。
- 保存的普通语音快捷键为 `ctrl+shift+space`，行为为 `hold_or_toggle`。短按切换开始/结束，长按松开结束。
- 初始输入控制显示“正在检查或停止”，日志每两秒停止快捷键监听。点击已有“重新检测并恢复”后，状态回到 ready，权限代数为 3；没有修改 macOS 系统授权。最初关闭原因已不在现存日志中，不能归因于某次休眠或权限撤销。
- 用户随后确认“能录音，但文字没有输入”。本次实体快捷键的按下/释放、录音采样与识别链路均有日志；新输出为 `pending_target`，目标 ID 非空，策略代数为 1，输出所有者为 platform。没有读取或归档用户语音正文。
- 系统设置记录选中的输入源为微信输入法。原平台语音路径无条件要求输入源类型为 KeyboardLayout，因此选中第三方输入法也会被当作组合未结束，阻止标准粘贴。
- 用户继续反馈切换输入法后第二次按键不能停止。20:25:26 普通路线开始录音，后续多次实体按键未触发停止，broker 却记录“没有活动 Host 会话的松键”；20:25:39 用户用 Escape 取消回到 idle。源码确认新出现的 Host 租约能抢走普通录音的后续边沿。

## 修复范围

- 仅语音平台路线的标准 Cmd+V 允许目标应用执行原生粘贴；不把属性缺省/不支持伪装成“输入法无组合”。公开 AX 属性报告正在组合、返回异常类型或发生查询错误时仍拒绝。
- 保留原字段、窗口、进程、选区、编辑通知、系统安全输入、权限代数、策略许可和取消检查。AX 查询前后输入源分类变化时拒绝；Direct、其他粘贴方法及历史插入不扩大范围。
- 自动 Enter 继续要求严格的无组合证明，与保留剪贴板的完成校验分开。未知派发不重试，派发成功不冒充目标应用确认接收。
- 拒绝日志增加固定阶段和状态原因，不记录正文。
- 权限组件停止且未探测时显示“已暂停”；恢复后清除检查中的临时消息，保留真正的失败提示。
- 原生快捷键的路由与 Start/Stop 改由同一协调队列决定：已有普通录音先处理后续边沿，只有未归属的新请求才询问 Host；保留实际按键时间，慢启动不把短按误判成长按，也不等待同步回执而丢松键。原有 Host 租约撤销与冻结目标合同不变。
- 产品文档入口、前端私有包、产品描述、请求产品名和本地热词提示词统一为 Inputia。真实远程地址、许可证、旧数据及配对身份保持兼容；没有宣称全仓所有历史标识均已迁移。
