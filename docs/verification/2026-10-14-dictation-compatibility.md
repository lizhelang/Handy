# Inputia 普通语音兼容性回归修复

日期：2026-10-14。本机已安装版本为 1.1.4 build 92；本文将源码、自动检查和实际使用证据分别记录。

## 根因与对照

对照最新上游 `53db4cb676bcb7831b94d95c716a67ddaaa2731a`（共同祖先 `fbd4e15fa14a721c66c57006ae110428b9e255b3`）：普通语音保存历史后直接进行系统粘贴，历史保存失败不阻止本次输出。上游没有要求目标应用公开 AX 字段、选区或编辑通知。

本项目 `2c6c6c66` 将精确目标与统一历史账本准入扩展到普通 macOS 语音。连同 Host 快捷键路由、字段 120 秒期限、短期输出许可及强制事务粘贴，增加了上游不存在的拒绝条件。现场有成功录音与识别之后 `UnknownTarget`、`target_Edited` 的证据，说明不能只归因于识别模型或用户按键。此前某次用户试用成功也不能证明所有应用均兼容。

界面另有独立缺陷：每个失败 operation 使用不同 toast ID，并设置无限时长。反复失败会永久堆叠；macOS 的可靠粘贴开关还被强制显示开启，与真实保存值不一致。

上游原文：[普通输出](https://github.com/cjpais/Handy/blob/53db4cb676bcb7831b94d95c716a67ddaaa2731a/src-tauri/src/actions.rs#L720)、[粘贴流程](https://github.com/cjpais/Handy/blob/53db4cb676bcb7831b94d95c716a67ddaaa2731a/src-tauri/src/clipboard.rs#L774)。这份对照不表示上游完全没有缺陷。

## 最终修复合同

- 普通全局快捷键固定进入本地录音协调器，开始和停止不再由 Host 租约或历史策略服务决定。
- 普通口述使用原应用当前光标的系统粘贴，不查询目标 AX 输入树，不要求历史保存或投影成功；保留前台进程实例、应用切换、系统安全输入、取消、权限和一次派发检查。
- 显式输入法会话和历史插入仍遵循原有精确目标及账本合同。没有把不明字段伪装成已确认目标，也没有失败后的自动重派。
- 尊重真实 `reliable_paste` 值。标准路径严格按“发布剪贴板→后台前延时→最后核验并发键→后台后延时→恢复”执行，前延时取消可恢复，已发键/结果未知不提前恢复。恢复核验 `changeCount`，用户新复制优先。
- 自动 Enter 仍需单独的严格目标证明，未启用时不发送；无法证明时跳过 Enter，不把已派发文字改为待插入。
- 通知合并为单条可关闭的 10 秒提醒；旧结果在历史中折叠展示，关闭提醒不删除、确认或重放账本。派发、结果未知和保存失败分别表述。
- macOS 粘贴设置显示真实值；标准粘贴可调整后延时，开启可靠粘贴后才隐藏该选项。

设计边界见[普通口述与精确目标输入](../architecture/ordinary-dictation.md)。原应用保护不等于同一聊天框证明，同应用内的当前光标遵循普通系统粘贴语义。
