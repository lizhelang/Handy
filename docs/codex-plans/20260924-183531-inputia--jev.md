## 1. 目标与关键判断

为 Inputia 增加一个本地判断模型层，用于分类、路由、有限候选选择、置信度评分和“是否需要调用更大模型”等任务，同时保留 Rime、ASR、SQLite、权限验证和输入提交的确定性边界。

这里的“类 JEV”指：给定状态和有限选项，返回 `choice / noul / score / confidence` 的判断模型。它不是语音识别器，也不是自由生成长文本的模型。

对 LiveCopilot 的核对结论是：当前公开主线已经有本地 Paraformer + Silero VAD、本地 BGE-M3、常驻本地 worker、下载校验和本地规则触发；公开文档没有把 JEV 列为现有 provider。我们借鉴它的本地模型工程方式，但把类 JEV 作为 Inputia 的新增判断层，不能把两者混成一个模型。

## 2. 当前项目基线

- `src-tauri/src/settings.rs` 已有本地 custom-word provider、Apple Intelligence、远程 provider 和 localhost OpenAI-compatible provider 配置。

- `crates/inputia-handy-runtime/src/personalization.rs` 已有选词反馈、近期/频次/上下文排序、撤销、遗忘和历史回填。

- Swift 输入法侧已有真实候选 ID、字段证明、学习世代、撤销和预测 admission 安全门。

2. Rime 拼音解析、候选 ID 映射、剩余拼音处理；
3. Tab、空格、数字选词、撤销和原生用户词典事务；
4. AX/字段/窗口/进程/敏感输入/权限/策略世代验证；
5. 文件路径安全、外部 AI 共享授权、Skill 访问范围；
6. 最终文本替换、数据库写入、历史删除和回滚；
7. 自动发送、自动提交或其他不可逆操作。

模型只能提出有限选项或评分，不能绕过这些执行器。

## 3. 交付后的用户行为

1. 简单转写纠错优先在本地完成，减少不必要的远程后处理。
2. 知识库查询先判断意图，再选择关键词、混合检索或向量检索。
3. 已有知识结果可以由本地模型做有限重排，但不增加每个按键的同步等待。
4. 语音、剪贴板和键入历史在进入知识库或个人学习前，获得本地类别、敏感度和“是否值得学习”判断。
5. 自动语音触发减少误报，同时保留手动快捷键兜底。
6. 本地模型不可用时，普通拼音输入、基础转写和关键词检索继续可用。

非目标：不用一个小模型替代 ASR、Rime、embedding 和长文本生成；不训练或蒸馏模型；不默认启用云端判断；不在每个拼音字符上同步调用模型；不把模型输出格式正确等同于业务正确。

## 4. 统一判断层架构

### 4.1 `DecisionProvider` 合同

新增与业务无关的判断接口：

- `noul`：返回是否满足条件的概率；
- `choice`：在有限候选中返回排序、概率和置信度；
- `score`：在固定等级中评分。

请求必须包含：`request_id`、`model_id`、有界 `state`、命名问题、候选 criteria、字符/问题/候选上限和 deadline。响应必须包含：实际模型 ID、权重摘要、答案、概率、置信度、拒答标志、耗时和固定错误类别。

不得把正文、拼音、候选原文、窗口标题、完整路径或密钥写入日志。模型响应必须由业务层再次校验，未知标签、越界概率、重复候选和过期 request_id 一律拒绝。

### 4.2 常驻本地 worker

采用与 LiveCopilot 相同方向的本机 worker：

- stdin/stdout 有界 JSONL，不开 localhost 监听端口；
- 单模型单并发，避免 Metal/Apple GPU 争用；
- 有最大输入字节、最大问题数、deadline、取消和关闭清理；
- worker 不继承外部 API key；
- 模型缺失、损坏、超时或崩溃时返回可见失败，不静默切云；
- 模型下载 SHA-256 校验、临时文件、原子替换和旧版本回滚；
- worker 退出只影响增强判断，不影响普通 Inputia 输入。

第一版只允许有限判断，不支持模型自由生成长答案。需要生成时继续使用现有 custom-word 或 post-process 专用路径。

### 4.3 模型注册和管理

注册信息包括：ID、名称、任务类型、权重文件、SHA-256、量化方式、许可证、最大输入、候选数、预计内存、设备要求、最小 macOS 版本、是否允许敏感判断、golden set 验证状态。

设置页必须区分“已安装、缺失、校验失败、加载失败、可用但未验证”，不能只判断文件存在。

### 4.4 第一版明确模型选择

第一版默认模型明确为：

```text
模型：Laya multilingual typed-decisions
权重：aac6fef/laya-multilingual-mlx
规模：约322M参数
精度：FP16
运行时：Apple MLX，独立本地 worker
平台：当前目标为 Apple Silicon（本机 M2 Max / 32 GB）
```

选择理由：这是专门做 typed decisions 的小模型，不需要生成长文本；多语言 checkpoint 更适合 Inputia 的中文/英文混合任务；MLX 是 Apple Silicon 原生路径，不依赖 PyTorch、CUDA 或 NVIDIA 显卡。公开项目在 M3 Max 上报告短判断约 P50 7.39 ms，但这个数字不是本机承诺，必须在 M2 Max 上重新测量。该项目也明确说明它是独立的 MLX 移植，不是官方 Convai 运行时，因此必须锁定 commit、权重 revision、SHA-256 和许可证后才可进入生产包。

第一版不会默认使用云端 Jev。云端 Jev 只允许作为开发阶段的可选对照基线，不能接收用户真实知识库、剪贴板、语音历史或输入正文，也不能作为训练标签。

第一版不会选择普通 PyTorch/CUDA 作为当前机器的默认路径。`local-jev` 的 Qwen 方案可以在 Apple Silicon 上运行，但它使用 Python/Transformers/PyTorch 路径；公开资料指出 Qwen3.5-4B 在 Mac 上的 PyTorch 路径没有 Apple GPU 快速路径，延迟不适合作为 Inputia 热路径默认。Qwen/Transformers/CUDA 只作为后续 Linux/NVIDIA worker 的兼容 backend，不进入当前 macOS 安装包。

`jevmlx` 或同类项目属于运行时/协议适配器，不是我们要选择的模型本身。它们可以作为接口参考，但第一版必须以实际锁定的 Laya multilingual 权重和本机 golden set 结果为准。

运行时落地分两步：P1 先用隔离的 MLX sidecar 验证协议、准确率和延迟；只有 sidecar 能通过模型许可、安装、签名、退出清理和离线运行验收，才决定是否将 Python/MLX 运行时随 Inputia 打包。若 Python 运行时导致包体、签名或启动风险超出预算，保留同一 `DecisionProvider` 合同，另做原生 MLX/Metal worker，不改变业务层接口。

## 5. 分阶段实施

### P0：基线和评测集

先固定现有行为和判断任务：

1. 测量后处理、知识库搜索、候选查询和历史回填的冷/热耗时。
2. 建立不含真实用户正文的 golden set：后处理是否需要修改、自定义词是否命中、知识查询意图、结果相关性、是否可回答、历史/剪贴板敏感度、语音问题/请求/陈述/取消分类。
3. 为每个样本设置人工标签、允许拒答和安全默认值。
4. 固定规则、本地生成模型、远程模型三种基线；禁止用远程 JEV 输出作训练标签。
5. 固定质量、拒答、延迟、内存和功耗门槛。

验收：无判断模型时所有原有结果不变；golden set 可重复运行并产生版本化报告。

### P1：worker、协议和模型管理

1. 实现 `DecisionProvider`、请求/响应 schema 和错误码。
2. 实现常驻 worker 的启动、健康检查、单并发、超时、取消、退出和重启。
3. 接入模型下载、SHA-256、磁盘检查、原子替换和回滚。
4. 增加模型状态 UI、模型版本和许可证显示。
5. 增加协议、恶意响应、过大输入、模型损坏、杀进程恢复测试。

验收：重复启动不加载多个模型；取消后旧响应不能回写；无网络、无 API key、模型缺失时普通输入和本地基础功能仍可用。

### P2：后处理路由和自定义词判断

在 `process_transcription_output` 之前增加本地 route decision，固定选项：

`keep / custom_word / punctuation_only / general_local / remote / abstain`。

规则：

- `custom_word` 才调用现有自定义词纠错；
- `remote` 且用户开启后才调用远程 provider；
- 所有替换继续经过现有 JSON schema、词表和范围验证；
- `abstain`、超时、低置信度和异常一律返回原文；
- 只记录路由类别、模型版本和耗时。

验收：无须修改的文本不被润色；自定义词质量不低于现有路径；异常不破坏原文；远程调用次数下降；关闭本地判断后可回退原流程。

### P3：知识库意图、结果重排和可回答性

1. 查询分类：`exact_lookup / definition / procedure / comparison / history_lookup / unknown`。
2. 根据意图选择关键词、候选扩展、embedding 或混合检索。
3. 对已经通过权限和 revision 校验的有限结果做 `relevant / partial / irrelevant` 或 0–3 分重排。
4. 增加 `answerable / insufficient_evidence / conflicting_sources` 判断，只影响回答策略，不影响权限。
5. 查询前先完成 enabled、external_access、revision、item_id 和安全路径检查。
6. 判断失败时回退关键词结果，并显示可见降级状态。

验收：应用内和外部 CLI 遵守同一授权和 revision 行为；来源撤销后不能被模型重新暴露；关键词回退可用。

### P4：历史和剪贴板分类

1. 分类普通文本、代码、地址、任务、个人资料、凭据疑似内容和短噪声。
2. 判断是否进入知识库、是否参与个人学习。
3. 规则扫描先于模型；凭据疑似、secure input、敏感字段和不确定内容默认拒绝。
4. 用户确认仍是最终授权，模型不能扩大来源范围。
5. 保持个人学习、全文收录、外部 AI 读取三个开关独立。
6. 保留 event_id、origin_revision、幂等、撤销和删除传播。

验收：重复回填不重复加权；删除来源后不可查询；拒绝的敏感内容不进入学习或外部读取；模型离线时规则和手动选择仍可用。

### P5：语音自动触发增强

1. VAD、稳定静音和现有规则仍是第一层。
2. 只对边界片段询问本地模型：`question / request / statement / cancellation / incomplete`。
3. `You`、敏感来源、未完成片段和低置信度不自动触发。
4. 模型超时或拒答时保持规则结果或不触发，绝不自动调用远程分析。
5. 只记录类别、置信度和耗时，不记录音频或正文。

验收：分别测量问题召回、陈述误触、取消识别、手动快捷键；实体麦克风和系统音频单独验收，不能用合成音频替代。

### P6：本地 embedding（独立于类 JEV）

只有 P3 稳定后实施：

- 固定 embedding 模型身份、维度和权重摘要；
- 文档向量、查询向量和旧 OpenAI 向量隔离；
- 后台批量、可取消、原子提交、失败保留旧索引；
- embedding 失败时回退关键词，不上传文本。

验收：重建、删除传播、模型切换、旧向量隔离和关键词回退通过。

### P7：候选二次重排（最后实施）

1. Rime 继续产生候选池和真实候选 ID。
2. 模型只接收有界候选摘要、前文摘要和当前拼音。
3. 只有 composition 稳定、字段证明有效、候选池已生成且预算满足时异步调用。
4. 回应重新校验候选 ID、composition、page、learning_epoch、target 和 selection generation。
5. 超时、Tab 早到、输入变化或模型失败立即回退 Rime 顺序。
6. 模型不能创建候选、直接插入文本或改变撤销事务。

验收：不阻塞按键；无上下文时原顺序逐 ID 不变；短码、纠错和不同 consumed_len/match_type 不跨组；真实实体键盘单独验证。

## 6. 隐私、权限和数据合同

1. 默认本机执行；未启用远程 provider 时不发送音频、正文、历史或知识片段。
2. 日志仅允许阶段、错误类别、耗时、数量、模型 ID 和版本。
3. 继续区分 `capture / retain / learn / remote_use / output`。
4. 外部 AI 知识库继续只读；模型不能调用写入、删除、导入或任意路径读取。
5. Secure Input、敏感窗口、未知字段证明和权限世代变化必须 fail-closed。
6. 禁用功能后，等待中的请求按 generation/epoch 失效；已发送给远程服务的内容无法撤回，UI 必须说明。

## 7. 性能预算和降级

这是待测工程目标，不是现有成绩：

- 后处理路由热启动 p95 ≤ 150 ms；
- 知识意图/重排 p95 ≤ 250 ms；
- 历史/剪贴板分类不阻塞前台；
- 语音判断不增加稳定静音窗口之外的阻塞；
- 候选二次重排不得同步阻塞按键，超时即回退 Rime。

所有数据在目标 Mac、固定模型、固定测试集下分别测冷启动和热启动。不得用单次 fixture 宣称达到搜狗、微信或 JEV 质量。

## 8. 测试矩阵

### 协议和 worker

合法/非法 JSON、未知字段、过大输入、过多问题、错误 request_id、单并发、队列满、超时、取消、崩溃重启、模型损坏和无网络启动。

### 业务 golden set

后处理路由、自定义词精确命中、错误词不替换、知识意图、结果重排、无证据/冲突证据、敏感内容、代码/地址、问题/请求/陈述/取消、候选池有限选择和原序回退。

### 安全与隐私

secure input、敏感窗口、字段切换、权限撤回、epoch 变化、external_access 关闭、revision 变化、来源删除、日志脱敏和 CLI 写操作拒绝。

### 原生验收

真实键盘候选翻页、Tab/空格/数字/撤销；真实麦克风和系统音频；知识文件增改删和断联重连；模型下载/取消/恢复；worker 崩溃后普通输入继续可用。

## 9. 交付物和回滚

每阶段必须交付代码、协议文档、模型来源/许可证/SHA-256、测试日志、性能报告、隐私检查和回滚步骤。模型安装失败保留旧模型；索引失败保留旧索引；判断模型关闭后恢复原路径；更新前备份设置、用户词典、知识索引和历史数据库。不得把合成 fixture、隔离模型测试或单次原生操作写成完整产品验收。

## 10. 顺序、停止条件和完成标准

固定顺序：`P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7`。任一阶段出现绕过权限、静默上云、热路径明显变慢、无依据改写、旧响应回写、关闭后仍学习/索引/发送、模型版本或评测不可审计，立即停止扩展并回滚。

计划完成必须同时满足：P0–P3 通过；P4/P5 已实现或明确延期并经用户接受；P6/P7 若未实施不得在 UI 宣称支持；模型、许可、数据源和评测可追溯；用户数据、设置、Rime 用户词典和知识来源保留；普通输入在模型失败、服务退出和权限变化后仍正常；最终安装包、签名、原生验收和回滚证据齐全。

1. 是否同意第一版固定使用 `aac6fef/laya-multilingual-mlx`，而不是云端 Jev、Qwen PyTorch 或 CUDA 模型；
2. 是否同意第一版只做本地 `choice/noul/score` 判断，不做本地长文本生成；
3. 是否先实施 P2 后处理路由，再实施知识库判断；
4. 是否同意 embedding 与类 JEV 判断使用两个独立模型和设置；
5. 是否允许下载并随包管理 MLX 模型及其运行时，接受内存/功耗/包体评估；
6. 是否同意候选二次重排最后实施，且不保证每个按键都调用模型；
7. 是否同意以项目 golden set 和实体验收为质量标准，而不是宣传性对比。
