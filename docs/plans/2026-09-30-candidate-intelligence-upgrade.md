# Inputia 候选智能化完整实施计划

日期：2026-09-30。状态：实施、验证及成对产物交付完成。

用户要求：前次提出的五个优化方向全部实现，先制定详细计划，再持续完成。工作区为 `Handy-unified-input-system`，起点 `70687eac`；当前聊天默认目录是旧分支，不在旧分支实现。

## 目标与交付

1. 快速输入时个人排序及时生效，异步结果不改变用户正在选择的对象。
2. 个人词、专名不受原生首批32候选的召回限制；分段选出的新词能按完整输入码再次出现。
3. 正确拼写保留合理优先级，确实拼错仍能纠正；文学词库不再把任意连续片段当作日常词条。
4. 从单一字面后缀提升到多词、分层上下文及近期句子搭配；以有界本地算法和既有可选模型接口评估效果。
5. 全局常用习惯与应用偏好结合；某语境拒绝一个词不等于永久忘记它。

交付包括源码、回归测试、固定离线回放和耗时证据、独立审查、原生构建产物、验证记录。测试语料不读取真实聊天或个人词库。代码/原生引擎/安装/实体键盘证据分别报告。

## 已核实的基线

- 新版已经有选词反馈、14天指数衰减、上下文增益、撤销和遗忘、零码预测。此次增强这些能力，不重复搭建学习系统。
- Swift 主机存在80毫秒调度等待，服务查询前另有120毫秒防抖。
- 首批个人排序取32个原生候选，CAPI最大64个；服务只能返回传入候选的ID顺序。
- 上下文主要由本字段确认上屏内容构成；公共搭配依赖词表拼接，跨应用共用偏好。
- 全拼额外纠错先加入纠错候选，足够时不再加入原输入。
- 诗词生成器对句子穷举2至8字片段；部分词条权重并非真实使用频率。

## 实施分工与顺序

### A. 排序、召回和反馈服务

负责 `crates/inputia-handy-runtime/src/personalization*.rs`、相应测试和 `src-tauri/src/personalization.rs`。

1. 兼容迁移 evidence，增加来源应用和输入方案维度；旧证据保留为全局证据，不猜测旧输入方案。
2. 保留全局弱共享，同应用证据给予有界增益；防止某应用大量重复使用压过其他应用明确偏好。
3. reject 绑定方案、输入码及上下文；空上下文拒绝只作用于相应无上下文输入。永久忘记继续使用已有管理动作。
4. 从已确认、未撤销、未遗忘的直接键入证据按准确方案/输入码召回，最多5项；不从历史全文猜测读音，不混用全拼/双拼码。
5. 在后缀精确匹配之外增加长度分层回退、最近词锚点和有界搭配评分；无证据保持引擎原序，保留消费长度/匹配类型约束。
6. 检查现有可选 local_decision_rerank 是否会覆盖个人排序。额外模型仅在可用且回放证明收益时参与，不新增云依赖或默认下载模型。

协议：Query/Feedback 增加向后兼容 `schema_id`；Query 新增 `recalled_candidates`，形状沿用 Candidate，使用 `learned:` 稳定ID、完整输入消费长度。Admit 增加默认空的 `input_code`、`schema_id`；服务端必须重查当前召回结果再准许上屏。关闭、遗忘、撤销及epoch变化同时影响排序、召回与接受。

### B. macOS 候选与快速输入

负责 Swift 主机、个人学习桥、连接结构及对应 selfcheck。

1. 合并两层固定等待，改为有界快速合并调度；缓存必须绑定方案、输入码、候选身份、字段、上下文版本、服务实例和学习epoch。
2. 反馈/拒绝/遗忘/策略变化时废弃相关缓存；过期请求与旧目标结果不可重新显示。
3. 用户开始导航或选择时冻结本次顺序；异步回复不能偷偷改变数字对应候选。
4. 合并召回词与原生候选；原生词继续按真实Rime ID选择，学习召回词经过服务端Admit与目标二次验证后提交。
5. 同一原始composition分段确认时累积完整输入码和文本，完成后学习整词。退格、取消、切换字段/方案、失效目标打断累积；撤销最后一段也撤销派生整词证据。
6. 提供明确的本语境拒绝动作，检查已有快捷键冲突；不把所有退格视为拒绝或误选。

### C. Rime 纠错与词库

负责 Rime adapter、真实引擎测试、词库生成与打包过滤。

1. 在临时userdb获取原输入和错误输入基线。
2. 原输入与纠错共同参与，纠错带置信度/代价，防止合法输入被修正结果挤出；保持可选择的原生地址及消费长度。
3. 词库生成保留可追溯完整诗句及明确词条，移除任意子串生成。现有词库的过滤过程必须可复现，并确实进入打包资源。
4. 保留正确输入、错拼、全拼与双拼分段选择、用户学习和撤销的回归；不对用户现有Rime userdb做清理。

### D. 集成与独立审查

主线程负责计划、跨层协议集成、额外回放、构建与交付；其他工作包不修改彼此所有权内文件。首轮实现后进行独立审查，重点关注学习污染、候选身份、方案混淆、快速选择竞态、迁移和撤销。

- 保留用户数据、权限、签名身份和现有设置；禁止真实个人库作为测试写入目标。

- 每个工作包完成后更新验证记录。Goal 只在五方向实现、必要检查、独立审查和交付证据齐全后完成；发现外部限制须明确说明，不能悄悄缩减范围。
