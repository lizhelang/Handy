# Inputia 类 JEV 本地判断模型融合实施计划（待用户评审）

状态：仅完成方案，不执行代码修改。用户检查本计划并明确同意后，才进入实现阶段。

## 1. 计划目的

为 Inputia 增加一个本地判断模型层，用于处理“分类、路由、有限候选选择、置信度评分和是否需要调用更大模型”等任务，同时保留 Rime、ASR、SQLite、权限验证和输入提交的确定性边界。

本计划不是把所有任务交给一个小模型，也不是把 JEV 当作语音识别或长文本生成模型。目标是把适合结构化判断的工作从远程大模型和过重的生成模型中分离出来，形成：

```text
确定性规则与安全校验
        ↓
本地类 JEV 判断模型（有限选项、可拒答、输出概率）
        ↓
专用模型或确定性执行器
        ↓
最终结果、输入提交或远程回答
```

## 2. 当前事实与范围基线

### 2.1 LiveCopilot 的可借鉴部分

当前公开的 LiveCopilot 主线已经采用了若干适合 Inputia 的工程模式：

- 本地 Paraformer + Silero VAD 负责流式语音；
- 本地 BGE-M3 负责知识库向量；
- 本地规则负责低成本的自动触发；
- 本地推理通过常驻 worker 和有界 JSONL IPC 运行；
- 模型下载有校验、取消、原子替换和失败回滚；
- 本地模型失败时可见失败，不静默把资料或音频切换到云端。

公开架构没有把 JEV 列为现有 LiveCopilot provider；类 JEV 判断模型是本计划要为 Inputia 增加的能力。LiveCopilot 的本地模型工程方式可以借鉴，但不直接复制其 Swift 代码或产品边界。

### 2.2 Inputia 当前可复用的基础

- `src-tauri/src/custom_words_model.rs` 已有本地 Qwen 自定义词纠错运行时、模型资源解析、受限 JSON 响应校验和失败后保留原文的路径。
- `src-tauri/src/settings.rs` 已有本地 custom-word provider、Apple Intelligence、远程 provider 和 localhost OpenAI-compatible provider 配置。
- `src-tauri/src/actions.rs` 已有转写完成后的语言转换、自定义词纠错和后处理流水线。
- `crates/inputia-handy-runtime/src/knowledge.rs` 当前以有界文本扫描和关键词检索为主，外部接口只允许 status/sources/search/read。
- `crates/inputia-handy-runtime/src/personalization.rs` 已有选词反馈、近期/频次/上下文排序、撤销、遗忘和历史回填逻辑。
- `src-tauri/src/managers/transcription.rs` 按实际模型 capability 区分流式和批量路径，并处理 ASR 的热词上下文。
- Swift 输入法侧已经有候选身份、字段证明、学习世代、撤销和预测 admission 的安全门。

### 2.3 当前明确不能交给判断模型的部分

以下部分必须继续由确定性代码或专用模型负责：

1. 音频采集、VAD、ASR 解码和流式字幕；
2. Rime 拼音解析、候选 ID 映射、剩余拼音处理；
3. Tab、空格、数字选词、撤销和原生用户词典事务；
4. AX/字段/窗口/进程/敏感输入/权限/策略世代验证；
5. 文件路径安全、外部 AI 共享授权、Skill 访问范围；
6. 最终文本替换、数据库写入、历史删除和回滚；
7. 任何高影响的自动发送、自动提交或不可逆操作。

判断模型只能提出有限选项或评分，不能绕过上述执行器。

## 3. 产品目标

### 3.1 用户可感知目标

1. 简单转写纠错优先在本地完成，减少不必要的远程后处理。
2. 知识库查询先判断意图，再选择关键词、混合检索或向量检索，减少无效检索。
3. 已有候选检索结果可以由本地模型做有限重排，但不增加每个按键的同步等待。
4. 语音、剪贴板和键入历史在进入学习或知识收录前，能进行本地的类别、敏感度和是否值得学习判断。
5. 自动语音触发更少误报，同时保留手动快捷键作为确定性兜底。
6. 本地模型不可用时，Inputia 仍能完成普通拼音输入、基础转写和关键词检索。

### 3.2 非目标

- 不追求用一个 0.6B/1.5B 模型替代 ASR、Rime、embedding 和生成模型。
- 不在本阶段训练或蒸馏模型，不把远程 JEV 输出作为训练标签。
- 不默认开启云端判断，不把本地历史自动发送给外部服务。
- 不在候选每次按键路径中同步调用本地模型。
- 不改变现有外部 AI 知识库只读权限模型。
- 不把“模型输出格式正确”当作“业务判断正确”。

## 4. 统一本地判断层设计

### 4.1 抽象接口

新增一个与业务无关的 `DecisionProvider` 概念，提供三类问题：

- `noul`：是否满足条件，返回概率和是否建议通过；
- `choice`：在有限候选中选择一个或多个选项，返回概率、排序和置信度；
- `score`：在固定等级或区间中评分。

建议的逻辑请求结构：

```json
{
  "request_id": "opaque-id",
  "model_id": "local-decision-qwen-1.5b",
  "state": {
    "text": "有一段已完成的转写文本"
  },
  "questions": {
    "route": {
      "type": "choice",
      "criteria": {
        "keep": "无需修改",
        "custom_word": "只涉及已授权自定义词",
        "punctuation": "只需标点或格式处理",
        "remote": "需要复杂改写或语义整理"
      }
    }
  },
  "limits": {
    "max_input_chars": 4000,
    "deadline_ms": 180
  }
}
```

响应必须包含：`request_id`、实际 `model_id`、模型版本/权重摘要、答案、概率、置信度、是否拒答、耗时和可诊断的错误类别。日志不保存正文、拼音、候选原文、窗口标题或密钥。

### 4.2 常驻本地 worker

采用与 LiveCopilot 类似的本机常驻 worker，而不是每个请求重新加载模型：

- stdin/stdout 使用有界 JSONL；
- 单模型单并发，避免 Apple GPU/Metal 上的并发争用；
- 请求有最大字节数、最大问题数和截止时间；
- 支持取消、关闭、重启和启动健康检查；
- worker 不监听网络端口，不继承外部 API key；
- 推理失败返回可见错误，不自动切换远程服务；
- 模型资源单独下载、SHA-256 校验、临时文件、原子替换和旧版本回滚；
- worker 退出后普通 Inputia 输入功能必须继续可用。

第一版只允许有限判断，不支持模型自由生成长回答。若后续需要生成，继续复用已有 custom-word 或 post-process 专用路径。

### 4.3 模型注册和能力声明

新增本地判断模型注册信息：

- `id`、显示名称、任务类型、模型文件、权重摘要；
- 支持的 `noul/choice/score` 类型；
- 最大输入长度、候选数、预计内存；
- 设备要求和最小 macOS 版本；
- 量化方式、许可证和来源；
- 是否可用于敏感内容判断；
- 是否经过当前 Inputia golden set 验证。

UI 必须显示“模型已安装 / 缺失 / 校验失败 / 加载失败 / 可用但未验证”，不能只显示文件存在。

## 5. 按任务分层实施

### P0：基线、协议和评测集

目标：在引入模型前固定当前系统行为和判断任务。

工作项：

1. 统计当前后处理耗时、知识库搜索耗时、候选查询耗时、历史回填耗时。
2. 建立不包含真实用户正文的合成 golden set：
   - 转写是否需要修改；
   - 自定义词是否命中；
   - 知识查询意图；
   - 结果相关性和是否可回答；
   - 剪贴板/历史是否敏感、是否值得学习；
   - 语音片段是否是问题或请求。
3. 为每个样本设置人工标签、允许拒答和安全默认值。
4. 固定本地、远程、规则三种基线，不使用 JEV 输出作标签。
5. 定义模型质量门槛、延迟门槛、内存门槛和拒答门槛。

验收：没有模型时所有原有路径结果不变；golden set 可重复运行并输出版本化报告。

### P1：本地判断 worker 和模型管理

影响范围：新增本地模型 worker、资源下载、设置页面、Rust 命令和测试。

工作项：

1. 实现 `DecisionProvider`、请求/响应 schema 和错误码。
2. 实现常驻 worker 的启动、健康检查、单并发队列、超时、取消和退出清理。
3. 接入模型下载、SHA-256、磁盘空间检查、原子替换和回滚。
4. 为本地模型添加设置页面和状态显示。
5. 让 worker 的失败只影响判断增强，不影响普通输入和已有本地 ASR。
6. 增加 worker 协议测试、恶意响应测试、超时测试、杀进程恢复测试和模型损坏测试。

验收：重复启动不加载多个模型；取消后没有旧响应回写；模型失败时有明确状态；无网络和无 API key 时普通 Inputia 可用。

### P2：后处理路由和自定义词判断

目标：优先改善最容易验证且不影响输入法热路径的任务。

工作项：

1. 在 `process_transcription_output` 之前增加本地 route decision。
2. 固定选项为 `keep`、`custom_word`、`punctuation_only`、`general_local`、`remote`、`abstain`。
3. 只有选择 `custom_word` 时调用现有 custom-word 修正器；只有选择 `remote` 且用户开启后才调用远程 provider。
4. 模型输出只能引用用户授权词表，最终替换继续经过现有 JSON schema 和范围校验。
5. `abstain`、超时、低置信度或响应异常均回退原文。
6. 记录路由类别和耗时，不记录转写正文。

验收：

- 不需要修改的文本不被润色；
- 自定义词命中率不低于现有 Qwen 路径；
- 模型异常不会破坏原始转写；
- 远程调用次数相比全量后处理下降；
- 用户关闭本地判断后行为可回到原有流程。

### P3：知识库查询意图、结果重排和可回答性

目标：提高现有关键词检索的命中质量，同时保持权限、来源和修订校验在代码中执行。

工作项：

1. 查询预分类：`exact_lookup`、`definition`、`procedure`、`comparison`、`history_lookup`、`unknown`。
2. 根据意图选择关键词、候选扩展、后续 embedding 或混合检索策略。
3. 对已经通过来源权限的有限结果做 `relevant / partial / irrelevant` 或 0–3 分重排。
4. 增加 `answerable / insufficient_evidence / conflicting_sources` 判断，仅作为回答策略，不作为删除或权限决定。
5. 任何模型判断前先完成来源 enabled、external_access、revision、item_id 和安全路径校验。
6. 模型失败时回退现有关键词结果，并在 UI/CLI 中显示“本地判断不可用，已使用关键词检索”。

验收：应用内搜索和外部 CLI 经过同一授权后，来源集合和 revision 行为一致；撤销来源后模型不能重新暴露已撤销文本；关键词回退可用。

### P4：历史和剪贴板的本地分类

目标：让用户已有语音、键入和剪贴板记录进入知识库或个性化学习前更可控。

工作项：

1. 判断内容类型：普通文本、代码、地址、任务、个人资料、凭据疑似内容、短噪声。
2. 判断是否值得进入知识库、是否值得参与个性化学习。
3. 规则扫描先于模型；疑似凭据、 secure input、敏感字段和不确定内容默认拒绝。
4. 用户确认仍是最终授权，模型不能自动扩大来源范围。
5. 保持个人学习、全文收录、外部 AI 读取三套开关独立。
6. 导入事件继续使用 event_id、origin_revision、幂等和可撤销语义。

验收：重复回填不重复加权；来源删除后不可查询；拒绝的敏感内容没有进入学习或外部读取集合；模型离线时仍可用规则和手动选择。

### P5：语音自动触发增强

目标：减少自动建议误报，但不影响手动快捷键。

工作项：

1. 继续使用 VAD、稳定静音和现有规则作为第一层。
2. 仅对边界片段询问本地判断模型：`question / request / statement / cancellation / incomplete`。
3. `You`、敏感来源、未完成片段和低置信度一律不自动触发。
4. 模型超时、错误或拒答时保持现有规则结果或不触发，绝不自动请求远程分析。
5. 记录触发类别、置信度和耗时，不记录音频或正文。

验收：问题和请求的召回、陈述误触率、取消识别和手动快捷键成功率分别测量；物理麦克风和系统音频验收单独进行，不用合成音频代替。

### P6：知识向量和本地 embedding

这不是类 JEV 判断任务，而是独立的 embedding 模型任务。只有在 P3 的意图和关键词基线稳定后实施。

工作项：

1. 引入本地 BGE-M3 或兼容 embedding 模型时，固定维度、模型身份和权重摘要。
2. 文档向量、查询向量和旧 OpenAI 向量按模型身份隔离。
3. 采用后台批量索引、可取消、原子提交和失败保留旧索引。
4. embedding 失败时回退关键词，不自动上传文本。

验收：索引重建、删除传播、模型切换、旧向量隔离和关键词回退均通过；报告真实延迟，不把单个 fixture 当生产 SLA。

### P7：候选二次重排（最后实施）

这是风险最高的一步，不进入普通每键热路径。

工作项：

1. 继续由 Rime 产生候选池和真实候选 ID。
2. 本地模型只接收有界候选摘要、前文摘要和当前拼音，不接受任意字段全文。
3. 只允许在 composition 稳定、候选池已生成、字段证明有效且模型预算满足时异步请求。
4. 响应必须重新校验候选 ID、composition、page、learning_epoch、target 和 selection generation。
5. 超时、Tab 早到、输入继续变化或模型失败，立即保留原 Rime 顺序。
6. 不允许模型创建候选、不允许模型直接插入文本、不允许模型改变撤销事务。

验收：每键输入延迟没有可感知回退；候选 ID 不错位；无上下文时原始顺序不变；短码、纠错和不同 consumed_len/match_type 不跨组；真实实体键盘测试单独完成。

## 6. 数据、隐私和权限合同

1. 本地判断默认只在本机执行；未启用远程 provider 时不发送正文、音频、历史和知识片段。
2. worker 日志只允许阶段、错误类别、耗时、数量、模型 ID 和版本；禁止正文、拼音、候选文字、窗口标题、路径中的隐私部分和 API key。
3. 模型输入有独立的 `capture / retain / learn / remote_use / output` 权限检查。
4. 外部 AI 知识库访问继续只读，模型不能获得写入、删除、导入或任意路径读取能力。
5. Secure Input、敏感窗口、未知字段证明和权限世代变化必须 fail-closed。
6. 用户关闭某一类功能后，正在等待的模型请求必须按 generation/epoch 失效；已发送给远程服务的内容无法撤回，需要在 UI 中说明。

## 7. 性能预算与降级规则

初始目标是工程预算，不是已经测得的结果：

- 后处理路由判断：热启动 p95 ≤ 150 ms；
- 知识库意图/重排：p95 ≤ 250 ms；
- 历史/剪贴板后台分类：不阻塞前台，单批可取消；
- 语音自动触发判断：不增加稳定静音窗口之外的阻塞；
- 候选二次重排：不得同步阻塞按键；超时即回退 Rime；
- worker 常驻内存、模型加载时间和功耗必须在设置页可观察。

所有预算必须在目标 Mac、固定模型、固定测试集和冷/热两种状态下分别测量。不能拿单次本地模型结果宣称达到主流输入法质量。

## 8. 测试与验收矩阵

### 协议和 worker

- 合法/非法 JSON、未知字段、过大输入、过多问题、错误 request_id；
- 单并发、队列满、超时、取消、worker 崩溃、重启和模型损坏；
- 模型版本变化后旧响应不能写回；
- 没有模型、没有网络、没有 API key 时的降级。

### 业务 golden set

- 后处理路由准确率、拒答率、误修改率；
- 自定义词精确命中、错误词不得误替换；
- 查询意图、检索重排、无证据和冲突证据；
- 敏感内容、代码、地址、凭据疑似片段；
- 问题/请求/陈述/取消触发分类；
- 候选池有限选择和原始顺序回退。

### 安全和隐私

- secure input、敏感窗口、字段切换、权限撤回、策略 epoch 变化；
- 来源 external_access 关闭、revision 变化、来源删除和缓存失效；
- 日志扫描确保不含正文、候选文本、拼音、密钥和完整路径；
- 外部 CLI/Skill 无法调用写操作或任意文件路径。

### 原生验收

- 真实键盘输入、候选翻页、Tab/空格/数字、撤销；
- 真实麦克风、系统音频、录音停止和模型切换；
- 真实知识文件新增、修改、删除、断联和重连；
- 模型安装、取消、恢复和应用重启；
- Inputia 主程序退出或 worker 崩溃后，普通拼音输入仍正常。

## 9. 交付物

每个阶段必须交付：

1. 代码与配置变更；
2. 模型来源、许可证、版本和 SHA-256；
3. 协议文档和设置页面说明；
4. 单元、集成、性能和原生验收日志；
5. 回滚步骤和保留用户数据的备份证明；
6. 明确哪些结果是合成 fixture、哪些是隔离模型、哪些是实体硬件验收。

最终产品文案不得使用“本地模型等同 JEV”“达到搜狗/微信效果”“完全离线回答”或“模型永远理解正确”等无法由验收证明的表述。

## 10. 实施顺序和停止条件

依赖顺序固定为：

```text
P0 基线/评测
  → P1 worker/模型管理
  → P2 后处理路由
  → P3 知识库判断/重排
  → P4 历史与剪贴板分类
  → P5 语音触发
  → P6 embedding
  → P7 候选二次重排
```

任一阶段出现以下情况必须停止扩展：

- 模型响应能绕过权限或来源校验；
- 失败后静默上传到云端；
- 输入热路径出现不可接受延迟；
- 模型输出导致原文被无依据改写；
- 旧响应在策略变化后仍能写回；
- 用户关闭功能后已有请求继续产生学习、索引或外部发送；
- 无法复现或无法审计模型版本、输入范围和评测集。

## 11. 用户评审时需要确认的事项

执行前请重点确认：

1. 是否同意第一版只做本地 `choice/noul/score` 判断，不做本地长文本生成；
2. 是否同意 P2 后处理路由作为第一阶段真实功能；
3. 是否同意知识库的本地 embedding 与类 JEV 判断分成两个独立模型和设置；
4. 是否允许后续下载约 1–4 GB 的量化本地判断/embedding 模型；
5. 是否接受候选二次重排必须最后实施，且不保证每键都调用模型；
6. 是否接受所有模型质量以本项目 golden set 和实体验收为准，而不是以 JEV、搜狗、微信的宣传或单次体验为准。

## 12. 计划完成标准

只有同时满足以下条件，才能将本计划标为完成：

- P0–P3 已实现并通过对应验收；
- P4/P5 的隐私和降级规则已实现，或明确记录为下一版本并得到用户接受；
- P6/P7 若未实施，必须在产品范围中明确排除，不能在 UI 中宣称已支持；
- 所有模型版本、权重许可、数据来源和测试集可追溯；
- 用户数据、现有设置、Rime 用户词典和知识库来源均保留；
- 真实模型失败、服务退出和权限变化不会破坏普通输入；
- 最终安装包、固定身份签名、原生验收和回滚证据齐全。
