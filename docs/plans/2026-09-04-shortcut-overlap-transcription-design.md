# 语音转写快捷键重叠修复设计

## 问题

HandyKeys 会把 `option_left+shift_left+space` 与 `option+shift+space` 同时匹配到左侧 Option、左侧 Shift 和 Space。当前设置允许普通转写和带后处理转写分别保存这两组字符串，因此一次物理按键会产生两个动作。第二个动作可能在转写处理中被记住，并在流水线结束后立即开始新录音，表现为悬浮条不消失且后续快捷键失效。

## 目标行为

- `⌥⇧Space` 保留给带后处理转写。
- 普通转写恢复为默认的 `⌥Space`。
- HandyKeys 拒绝任何与已启用快捷键发生物理重叠的新配置，而不只比较字符串是否相同。
- 启动时发现历史遗留冲突，应确定性地保留带后处理转写，并把普通转写恢复为默认值。
- 合法的左右修饰键区分继续可用；只有两组快捷键能被同一次物理按键同时触发时才算冲突。

## 实现边界

在快捷键层提供可测试的重叠判定，并让设置变更、启动注册共享同一规则。状态机仍保留“处理中记住真实新按键”的能力，不通过粗暴吞掉跨动作事件来掩盖配置错误。

## 验证

- 单元测试覆盖通用修饰键与左/右限定修饰键的重叠关系。
- 测试现有冲突配置会恢复普通转写默认键，同时保留带后处理转写。
- 测试合法的不同按键及互斥左右修饰键不会被误判。
- 运行快捷键、设置和转写协调器相关 Rust 测试，再执行格式检查与生产构建。
- 替换 `/Applications/Handy.app` 后，用实际快捷键连续执行至少两轮转写，确认每轮粘贴后悬浮条消失且不会自动开启下一轮。
