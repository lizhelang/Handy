## 两种明确不同的输入意图

| 路径                     | 语义与必需条件                                                                                                                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 普通全局口述             | 默认在实际插入时的当前前台应用进行一次系统粘贴；可选固定开始录音的应用实例。需要本次会话、取消、安全输入与系统权限检查有效；不要求 AX 字段、Host 租约、历史投影或 120 秒字段期限。 |
| 显式输入法会话、历史插入 | 保持原字段、选区、组合状态、策略版本和账本证明。不能失败后自动降级到另一条路径。                                                                                                   |

“高级 → 输出 → 语音插入位置”提供两种模式，开始录音时冻结本轮选择：

- **插入时的当前光标（默认）**：开始时不捕获前台应用；实际准备与发键前读取当前前台，不要求进程创建时间或 AX 字段。录音和识别期间可切换应用，最终系统粘贴跟随当时的光标。
- **开始录音时的应用**：捕获开始时的进程实例。讲话期间可以切走再切回；插入前须回到同一实例，PID 被新进程复用也拒绝。不自动激活原应用，不保证原窗口或聊天输入框。

两种模式均不读取窗口标题、输入正文或 AX 输入树来决定普通粘贴目标。开始录音时若安全输入已开启，本轮不自动派发；准备和发键时也重新检查安全输入，并排除 Inputia 自身。普通系统粘贴不能确认任意第三方应用是否实际接收文字，`dispatched` 仅表示已派发。

历史保存失败单独报告，不能阻止本次普通输入。新普通口述不伪造 AX token，也不向旧的严格账本填入虚构目标；进程内的本次会话只取得一次派发权，任何可能已发出的输入都不自动重试。

## 剪贴板与自动发送

- 普通口述尊重用户的粘贴方式和 `reliable_paste` 设置。标准路径直接发布普通文本；可靠粘贴保持独立路径，失败后不盲目重派。
- 等待用户配置的前后延时放在后台，主线程只准备、核验和执行原生动作；延时不能被两秒字段许可截断。
- 标准粘贴保留每个 item 可兑现的格式。可选私有格式缺失时仍保留其余文本、图片和文件表示；原非空 item 完全不可恢复时在写剪贴板前拒绝。
- 恢复旧剪贴板始终检查真实 `changeCount`，用户期间的新复制优先。已发键后的取消不提前恢复旧剪贴板，避免排队的 Cmd+V 读到旧内容。
- 自动 Enter 仅在用户启用且额外严格目标证明有效时尝试；普通粘贴可用不等于允许自动发送。跳过 Enter 不把已派发的文字改报为“尚未插入”，更不能再次发送整段文字。

## 通知与验证

实时故障只使用一条可关闭的限时通知，正常 `dispatched` 不显示为故障，也不冒充应用已确认接收。真实 `uncertain` 保持不确定；保存失败文案不能声称结果已在历史里。

本轮输出结果日志只记录固定白名单 `state`、`history_saved`、`stage`、`reason`，包括提前返回；未知错误归类为 `unclassified_error`。不写入转写正文、剪贴板格式或原始脚本错误。该诊断仅覆盖新增普通口述结果记录，不表示已审计全部历史日志。

旧账本结果继续保存在历史收件箱，默认折叠显示；打开历史、重新挂载或查询迟到不能逐条反复弹窗，关闭通知不自动改写账本状态。

验证须分别记录：代码回归、私有命名剪贴板的原生验证、真实用户试用。合成测试不证明微信或所有自定义输入框已实测通过。本轮不操作用户的微信窗口、登录或安全验证。
