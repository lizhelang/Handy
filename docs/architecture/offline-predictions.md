# Inputia 离线联想边界

日期：2026-10-14。用户已明确选择：输入时完全在本机执行，网络仅用于事先取得或后台更新模型、词库等资源。本文区分当前修复与待质量验证的模型路线，不表示所有部分已经安装。

## 输入与资源

普通按键不等待网络、数据库、IPC 或模型推理。已有 Rime 与本地通用词库继续提供基础候选。联网取得的资源应绑定固定版本、来源、许可证、文件大小与摘要；完成下载和校验后才能启用。输入内容不作为资源更新请求的载荷，不通过远程 API 生成实时推荐。当前没有配置新的周期任务或自有模型更新服务器，不能宣称已具备自动后台模型更新渠道。

本轮正在修复连续选择、过期捕获排队与前文丢失。前文只来自当前输入法实际完成的插入，最大 512 个 Unicode 标量；同服务、同字段身份及光标连续证明齐全时才合并。窗口的五秒生命周期与前文缓冲独立；词库学习反馈仍限定 64 个标量，不把长查询上下文补写为历史或学习。选区、字段、会话、隐私或安全状态变化时按相应边界撤销。

## 公共二元表与合并打分（2026-10-23，分支 `codex/prediction-ngram`，1.1.31 起安装，1.1.32 调整个人层与按键，1.1.33 加入历史词对）

空输入联想在数据目录登记了二元表时改用新路径；未登记、资源缺失或格式不符时退回原有词库补全，基础输入不受影响。

- 资源：`prediction-ngram.sqlite` 由谷歌图书 Ngram 第三版简体中文一元、二元文件在构建时离线生成（CC BY 3.0，来源与摘要固定在 `scripts/prediction-ngram.lock.json`），随应用打包，只读打开，不复制进学习库。主应用启动时登记路径与摘要。
- 公共概率：前文末尾按词表反向最长匹配得到最后一个词 X，下一个词 w 的概率为 `count(X, w) / (count(X) + extend(X))`，`extend` 是以 X 开头的更长词的次数之和；X 没有续写时退到更短的词并乘 0.4。前文末尾不是汉字（标点、英文、数字）时没有公共续写。公共补全在开发集上几乎不命中，默认权重为 0。
- 个人概率：下一个词只认两种证据——完整前文相同（原权重）与前文最后一个词相同（乘 0.5，按前文末字的表达式索引取回后核对整词）。只有片段重合不计入；"前文 + 该词"正好是当前前文结尾的记录是刚上屏的这一步，不再推荐。以 X 开头的已学短语按一半权重作为补全。本机历史开发段上，这一规则比 1.1.31 的片段重合更准；另设最低证据门槛或同时计入片段重合都会降低首选命中，因此均不启用。
- 历史词对（1.1.33）：用户在控制中心确认回填时，语音与键入正文按联想词表正向最长匹配切词，相邻词对按来源与修订写入 `history_bigrams`，触发器维护 `history_bigram_totals` 汇总；每出现一次计 0.1 个人证据（开发段上 0.05–0.5 差别很小）。上屏后联想不再读取导入整句（开发段上整句降低命中且需逐条核验来源）。展示前对含历史贡献的候选按次数每批 8 条核对来源，至少一条现存才展示，失效来源即时撤销并使本轮作废；未抽到的失效来源由后台核对扣除，只影响排序。学习库与来源库的只读连接在查询间复用，库文件身份变化时重新打开。
- 合并：`P = (1-λ)·P公共 + λ·P个人`，`λ = n / (n + 1)`，n 为保留的个人证据总量；低于 0.003 不展示，最多 3 项、不显示编号，空格选当前高亮项，左右方向键与 Tab 移动高亮。遗忘、语境拒绝与敏感应用规则不变；ID 仍为 `learned:` / `base:`，协议不变。准入重查上限 9 项。

## 问号、感叹号与表情（2026-10-26，1.1.34）

- 资源：联想表格式 2 增加 `punct`（每个词后紧跟 `, . ? ! ; :` 的次数，来自同一批谷歌图书二元文件）与 `emoji`（词→表情，来自 Unicode CLDR 48.2.3 中文注释、Unicode 16.0 emoji-test、rime-emoji 与自写口语词表）。格式 1 的表仍可读取，只是没有标点与表情。
- 问号：当前分句以疑问语气词结尾时，概率为公共表中"该词后是问号"的比例，可以排第一；有疑问词、正反问或"A 还是 B"线索且线索离句末不超过 8 字时，概率取 `max(P(？|X), 2 × P(句末|X))`，最多排在第一个续写之后；句末是实义词的正反问（"难不难"）或"……过没有"至少 0.1。转述与宾语从句（"他问我去不去""不知道为什么"）、任指（"什么都行""想吃什么就点什么"）、条件、交给对方决定、建议的"吧"与"在……呢"不算问句。低于 0.05 不展示。
- 感叹号只在感叹线索（"太……了"、程度词加"啊/呀"、句首"哇/天哪"）下出现；句号、逗号不由公共表给出，只可能来自用户自己选过的标点。
- 合并：标点与续写同一标尺排序，但不随个人证据总量折减（个人层在标点处断开，对标点没有反面证据）；每轮最多一个标点。标点跟随同一段文字里汉字后已用的全角或半角，没有时给半角，与输入法"中文下用英文标点"的默认一致。
- 表情：前文末尾的连续汉字以表情词完整结尾（不是更长词的后半截）时给一个表情，固定第二位；末尾语气词（了、啦、啊等）去掉一个再匹配；单字词（冷、累、困）须跟在程度词后；否定词之后不给。遗忘、语境拒绝、敏感应用规则不变。
- 验收：调参只用开发集；首次测试判定中 T4 测试段一项（陈述句末误出问号 11.4%，门槛 10%）未过，此后该段转为第二开发集，另由独立 agent 新写 T5 作终验并全部通过；详见 [1.1.34 记录](../verification/2026-10-26-prediction-punctuation-emoji-1134.md)。

## 可选本地模型的接入条件

先验证中文续词质量，再接入模型。单独推理程序的速度不等于成套应用的端到端速度；测试必须保留上下文、原始输出、资源版本与反例。不能以输出形状正确或几个固定例子成功代替日常语义质量。模型不合格时保持关闭，已有输入继续可用。

若通过质量门槛，首版采用独立本地预测进程、一个当前任务和有界已发布快照，复用原 Query/Admit 与最终字段证明。模型工作不与语音纠错共用阻塞锁或进程。首个有效 Query 立即给现有词库结果，后台只计算短续词；未完成结果不能作为可选候选。后续读取仅可向当前列表末尾追加空余编号，选择开始后冻结，不能改变已有空格/数字映射。

已发布的模型候选有独立身份，绑定原字段、服务/客户端、完整上下文、策略代数、模型版本及固定截止。选择时必须精确匹配已发布结果，并重新检查遗忘/拒绝、原字段及权限。不得伪装词库或学习候选，不在选择时再次生成文字。插入仍至多一次，不自动重放。

后台私有上下文与原生推理资源须登记实际存活读者；失效、超时或撤销时清理队列、缓存及原生上下文，必要时终止并回收预测子进程，之后才释放读者证明并确认清理。诊断仅记录固定状态、耗时与计数。

## 当前探索证据

- 通用词库：356,723 条公开条目，独立运行 100 次生产查询，debug p95 为 5.715ms。这不包含跨进程及原生输入框交接。
- 苹果设备端模型：12 个新测试场景、3 个提示/预热配置。完整候选中位约 521–698ms，存在明显拼接错误，当前不接入默认候选。见[留出实验](../verification/local-prediction-20261014/apple-system-model/report.md)。
- Qwen3-1.7B-Q8_0：官方固定权重摘要已核验。初轮 raw 14/20 有用，完整自然候选 p50/p95 为 24.68/45.23ms；长上下文不足。使用的官方测试 runtime 与产品 Rust runtime 不同，不能沿用为产品承诺。见[初轮实验](../verification/local-prediction-20261014/qwen-initial/report.md)。

最后一轮固定协议使用 20 个新普通场景和 4 个长段落场景，由独立 agent 冻结题目、root 匿名一次评分。raw 有用项 10/20、few-shot 6/20，长段落均 2/4；人工分档只是该组公开合成文本的判断，不是用户准确率。见[完整结果和可复跑归档](../verification/local-prediction-20261014/qwen-final/report.md)。两种模型均没有接入默认候选，神经语义质量仍未解决。没有新增模型后台下载任务，没有读取真实聊天数据或公开发布制品。
